Kodrix IDE Documentation

Welcome to the official documentation for Kodrix IDE. This guide covers how to effectively use the IDE, understand its internal architecture, use frameworks, and troubleshoot common errors.

1. Getting Started: What You Can Do

Kodrix is a complete development environment on your phone. You can:

  • Write Code: Multi-tab editor with syntax highlighting for popular languages.
  • Run Commands: Open the terminal and use node, npm, git, and standard Unix commands (e.g. ls, cd, cat, grep).
  • Build Web Apps: Run npm run dev to start web frameworks like React, Vite, or Vue, and view them via the built-in browser tab at localhost.
  • Version Control: Use the git command to clone repos, commit changes, and push code back to GitHub.

Example - Running a simple Node.js script:

# 1. Create a file
echo "console.log('Hello from Kodrix!');" > test.js

# 2. Run the file
node test.js

2. Architecture & File System

Because Android enforces strict sandboxing, Kodrix maintains its own isolated virtualized filesystem located inside /data/data/com.kodrix.zohaib/files/.

  • /usr/bin/: The primary executable path. This contains the active wrapper scripts for tools like Node.js and Git. When you type node, the system looks here first.
  • /usr/bin_safe/: The fallback directory. Contains static, unbreakable wrappers pointing strictly to the IDE's bundled runtimes. Used only during Safe Mode.
  • /usr/lib/: Stores required shared libraries (.so) for downloaded runtimes.
  • /npm_pkg/: The global NPM directory. Running npm install -g installs packages here to bypass Android permission restrictions.
  • /runtimes/: Stores downloaded alternative versions of tools from the Marketplace.

3. Marketplace & Beta Mode

The Kodrix Marketplace allows you to hot-swap internal runtimes and download new versions without updating the entire app.

Bundled vs Downloaded Runtimes

Kodrix ships with Bundled versions of essential tools (e.g., Node.js v25.8.2, Git v2.34.0) pre-compiled for Android's Bionic libc. If you need a different version, you can download it via the Marketplace.

Beta Mode

Certain runtimes are experimental and hidden by default.

  1. Open the IDE Settings.
  2. Scroll to Developer and toggle Beta Mode.
  3. The Runtimes tab will now be visible in the Marketplace.
  4. You can now download and test beta versions of Node.js or Git.

4. Working with Web Frameworks

You can run modern frameworks directly on your device. Use the terminal to scaffold a project:

# Scaffold a Vite React app
npx create-vite@latest my-app --template react

# Install dependencies
cd my-app
npm install

# Start the dev server
npm run dev

Once the server starts (usually on port 5173), open Kodrix's internal Browser tab and navigate to http://localhost:5173.

5. Troubleshooting & Error Fixes

Mobile architectures can occasionally cause binary linking errors. Here is how to resolve the most common ones.

Error: CANNOT LINK EXECUTABLE: library "libffi.so" not found

Cause: You downloaded an experimental Node.js version (like v26.2.0) that depends on a shared library missing from your device.

Fix: Open the Marketplace and activate the Bundled (v25) or a stable LTS version instead.

Error: CANNOT LINK EXECUTABLE: library "libz.so.1" not found

Cause: A downloaded Git binary is failing to link with the bundled zlib.

Fix: Switch your Git version back to v2.34.0 (Bundled) via the Marketplace.

Error: Permission denied when executing a script

Fix: You must make the file executable. Run chmod +x script_name.sh.

Emergency Recovery: Safe Mode

If a broken downloaded runtime crashes your terminal instantly, you can recover by using Safe Mode:

  1. Go to Settings > Environment and enable Safe Mode.
  2. Restart the Terminal. The terminal will now strictly use the stable, bundled binaries (ignoring any broken downloaded versions).
  3. Open the Marketplace, switch your active runtime to the Bundled version.
  4. Go back to Settings and turn Safe Mode OFF.
